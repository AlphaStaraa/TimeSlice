# 1.0.7 预览花屏修复

桌面完整版、Lite和Windows共用的视口渲染器在1.0.6中没有传入高精度缓存的色彩标记。选择10位输出，或导入PQ/HLG素材、启用调色后，预览可能把每像素四字节的RGB10布局当成RGBA8读取，形成彩色噪点、色带和明显分层。正式导出使用另一条已设置色彩标记的路径，因此本次反馈表现为预览异常而成片正常。

1.0.7在视口入口根据实际缓存确定源布局、原色与传递函数，预览始终输出SDR RGBA8，即使导出设置选择PQ或HLG，也不会把RGB10成片字节直接交给普通预览纹理。该修复同时适用于CPU和GPU，不改变正式导出的10位规格、效果公式、阴影或码率。

## 验证

- 修复前，新测试中的16组CPU预览像素对照均失败；修复后通过。测试使用独立NumPy灰阶/PQ/HLG显示参考，并检查HSL及四种冻结形状。
- 新增两项回归后，共31项真实CPU、Metal GPU及编码测试通过，无跳过。
- 用户的真实上海20秒视频采24个时间样本作为预览源，另用原生PQ/HLG样片；46效果、两处时间进度、调色开关共552组CPU/Metal预览对照通过，最大平均通道差约0.0033/255。
- 旧1.0.6 Windows实机通过29项回归、92标准帧、92项CPU/GPU对照、四格式短片与取消清理；该结果不能作为新1.0.7包已实机通过的证明。
- 本轮已取回363项Windows证据文件并核对清单；31视频共348帧在Mac重新完整解码，逐帧MD5与Windows一致。原ZIP被浏览器解压，使用分文件校验，不声称重新计算了原ZIP总哈希。

完整20秒、1200源样本的4K60 PQ测试此前因低内存保护取消。此项与预览格式误读分别记录，当前修复不包含尚未Windows验证的按块FileIO实验。不能声称长片内存问题已解决。

## 更新

退出旧版本，完整解压新压缩包后运行。Windows须保留包内app、assets、runtime等目录；Mac需使用新App。版本应显示1.0.7。保留原片，并在分享之前检查成片。

此版不重新发布Android；Android保持独立版本1.0.5-hdr-preview.1。源码继续采用AGPL-3.0-only，由用户自行提交、推送和发布。
