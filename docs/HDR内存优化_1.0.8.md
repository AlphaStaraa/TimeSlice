# 1.0.8 · HDR长源内存读取

Windows上逐块整理长源时，NumPy映射读取会使大量源页面进入进程工作集；原来的mmap.madvise回收提示不适用于Windows。先前32GB设备的完整20秒4K60 PQ测试在合成约40%时可用内存降至约492MiB，被测试保护取消。

1.0.8在Windows GPU空间分块路径中，对超过4GiB的完整只读帧映射自动使用文件readinto。正常源块由现有GPU预算限制在192MiB内，文件读取接口另限制单块不超过256MiB。线程各自使用独立句柄，并正确处理短读、文件偏移和连续时间子视图。内存源、写时复制及非连续视图继续读取它们的内存内容，避免丢失尚未落盘的编辑。

HDR解码后的峰值统计同步改为8MB流式扫描，扫描全部像素及RGB三通道，忽略最高两位填充值。峰值与原算法一致，缓存仍为每像素四字节RGB10。分辨率、帧率、全部时间样本、效果公式、调色、阴影和输出规格不变。

## 完整导出验证

受测Windows为32GB内存、Ultra7 255HX、RTX5060 Laptop/Vulkan，编码使用HEVC QSV。以用户真实上海20秒原片、3840×2160/60fps、实际1200源样本、60切默认阴影，关闭稳定、去闪和风格调色，输出20秒1200帧Main10 PQ；保留原可用内存低于1.5GiB持续8秒的取消保护及临时防休眠。

- 独立实验读取：完整成片与1200帧解码通过，用时212.23秒；最低可用内存14.71GiB，采样监测的主进程工作集峰值约515MiB。
- 纳入生产函数：首份完整导出209.41秒，成片SHA与上述实验成片完全一致；40项真实CPU/GPU/编码回归及92标准帧通过，未降低阈值。
- 编码PQ输入→PQ的生产全长复验通过：305.10秒，实际1200源样本及1200输出帧，流式峰值扫描实际调用1次，文件分块实际调用216次；SPS10位、Rec.2020/ST2084/矩阵及逐帧完整解码通过。该输入由真实上海SDR映射生成，是有效PQ编码，不称为相机原生HDR素材。
- 两次正式函数路径的最低可用内存分别14.89GiB、14.62GiB，监测主进程工作集峰值分别约515.6MiB、516.0MiB。原低内存保护未触发，取消及缓存清理通过，生产模块文件SHA未变；107和106原件均保留。

上述耗时为该设备单次观测，原低内存取消没有有效整片耗时，不能据此宣传固定加速倍数。主进程工作集不等于整个系统、GPU及FFmpeg总内存。

完整1200样本的4K缓存仍约39.8GB，空间暂存成片另约39.8GB，工作盘仍需足够空间。改善的是内存读取和工作集，不减少源样本或偷偷降低画质。Windows CPU逐帧合成与开启完整尺寸稳定/去闪的负载需分别验证，不能将本GPU导出数据泛化到所有功能和设备。
