# GitHub发布指南

此文件描述准备和发布顺序。源码、附件和发布文案在本地就绪，不代表仓库或Release已经创建。

## 仓库

使用准备目录内的`TimeSlice/`作为仓库根目录，包含源码、协议、文档和CI。不要从包含SDK、缓存、素材和维护记录的开发工作目录直接执行`git add .`。

仓库初始分支为`main`，文件已暂存供检查，不预填维护者的Git邮箱。提交前使用自己的公开作者信息，检查`git diff --cached --stat`，再创建首个提交。之后将远程地址设为你自己的GitHub仓库；本轮没有连接任何远程仓库或执行push。

建议公开仓库描述：`Free, open-source timelapse slicing for macOS, Windows and Android. Made by AlphaStar.`

建议Topics：`timelapse`、`video-processing`、`time-displacement`、`qt`、`pyside6`、`wgpu`、`android`、`agpl-3-0`。

首次上传后开启Issues和Private vulnerability reporting；主分支保护可要求`source`、`numerics`、`lite-quality`和`android`检查通过。GitHub工作流只有上传后才真正执行，不能预先把本地通过结果当作云端CI通过。

## 本地复核

```sh
python tools/verify_source.py
python tools/index_functions.py --check
python tools/audit_publication.py --source . --report build/publication-audit.json
python tools/check_desktop.py --cpu-only
python tools/golden.py
```

审计在Git仓库中检查暂存/已跟踪文件，在干净源码目录中检查全部文件。发现密钥、个人路径、安装包、SDK或超过GitHub文件上限的内容时应停止上传。报告不会输出疑似凭据原文。

## Release

当前准备的首个GitHub版本建议为`v1.0.4`，勾选**Pre-release**。它包含Mac完整版/Lite1.0.4、Windows1.0.4视频切片预览、Android1.0.3视频切片预览，不把不同平台强行改成同一版本号。

把`发布附件/`中的平台文件、`TimeSlice-source-1.0.4.zip`和`SHA256SUMS.txt`一起附到Release，粘贴准备好的中英文发布说明。先保存为Draft，检查资源名称、源码入口、校验和与实际下载，再选择发布。

应用ZIP和APK不提交到Git。GitHub单文件仓库限制与Release附件限制不同；本项目源码归档中的固定第三方源码包均低于仓库文件上限。

当前发布附件沿用已实测的程序执行文件，新增文档/源码封装不构成新的性能测量。Mac为本地签名测试包，未Apple公证；Windows实测的是独立副本，不能写成最终ZIP已在Win解压验收；安卓实机范围和源样本限制见验证矩阵。

## 第三方与素材

自有代码为AGPL-3.0-only，允许商业使用与收费分发。保留全部许可证和对应源码入口。具体依赖版本、源码归档和上游二进制来源见[第三方源码说明](第三方源码说明.md)；应按实际构建核对依赖的分发义务，不把本项目的协议替代依赖协议。

公开源码仅含示例视频和必要预览资源，私人摄影序列、原始测试片、签名密钥与设备日志不上传。界面字体来自系统，源码不再分发字体文件。
